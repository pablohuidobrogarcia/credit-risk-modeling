01The problem and the data

Lending Club publishes every loan it originated, with the outcome as of the end of 2018. The task is the one a lender actually faces: estimate how much of a portfolio will default, how much is lost when it does, and how much capital the tail requires.

Of 2,260,668 originated loans, 1,345,350 have reached a final status (Fully Paid, Charged Off or Default). A loan is labeled default when its status is Charged Off or Default; the overall resolved default rate is 19.96%.

The primary model is trained on the 2010–2013 vintages and evaluated, once, on the 2014–2015 36-month vintages (12.4% and 14.5% default rates). The test window is used only for the final number — never for tuning.

Why this split matters. The dataset is a snapshot: recent loans are mostly still open, so their outcomes are unknown. Choosing the validation window carelessly is the single most common way to fool yourself with this dataset — see the next section.

02The pitfall: right-censoring

A loan can only be scored as paid or defaulted once it has finished. In a snapshot, the finished loans are not a random sample of the portfolio: which loans have an outcome, and when, depends on the vintage. This is the headline finding of the project.

Only resolved loans enter the sample, so early defaults and early prepayments are over-represented relative to loans that are still open. The censored 2017-2018 window has a higher observed default rate (21.29%) than the mature 2014-2015 window (14.46%), and its loan composition differs, so its AUC is not comparable. The +0.0580 AUC gap is a measurement artifact of the sampling; the censored window is shown only to quantify it and feeds no headline number.

04Calibration, LGD and expected loss

A score only becomes money once it is calibrated to a probability and combined with loss given default. Both steps here are reported as they stand, including the null results.

Calibration is a null result.

Recalibration barely changes the Brier score (raw 0.11949 vs calibrated 0.11970); calibration-in-the-large moves from 0.1844 to 0.1986. The selected method is isotonic, and no method beats the raw score. Every decile lies above the diagonal, so the score under-predicts default: on the test window the calibrated score is 2.3 pp below the observed rate.

Loan-level LGD is not usable. Every LGD model has a negative out-of-time R² — worse than predicting the mean. There is real signal in the loss-rate distribution (the share of zero-recovery defaults rises from 5.2% in training to 26.9% out of time), but per-loan prediction does not generalize, so expected loss uses a portfolio-level LGD (0.8678 realized out of time).

06What did not work, and limitations

Kept visible on purpose. A portfolio that only shows its wins is not a portfolio you can trust.

  • Discrimination is moderate (champion Gini 0.3144); the lender's own grade still adds about 0.0227 AUC.
  • Loan-level LGD is not usable (every model has a negative out-of-time R-squared).
  • Probability calibration is a null result: isotonic did not improve the test Brier (0.11949 raw vs 0.11970 calibrated).
  • The monthly default-rate forecast is beaten by a naive benchmark (last-value naive MASE 0.5543 vs SARIMAX 1.1319).
  • Antithetic variates give a negligible variance reduction (reported, not hidden).
  • No macroeconomic variables; the data ends in 2018, so only one credit cycle is observed.
  • Reject inference is exploratory only and feeds no headline number. The data contains approved loans only, so the selection bias cannot be corrected.

Silhouette 0.1840, stability ARI 0.9566. k-means separates the default rate by only 0.54 pp; a Gaussian mixture separates more (6.28 pp) and is at least as stable (bootstrap ARI 0.9785 vs 0.9566). Neither is used as a model feature.

Selection bias

The data only contains approved loans. An exploratory reject-inference pass suggests the rejected applicants would default more often (illustrative PD gap 0.0576), but rejected applicants have no observed outcome, so the gap cannot be validated. It is labeled exploratory and feeds no headline number.

07How to reproduce

Everything is deterministic (seed 42). The pipeline runs from raw CSV to the figures and this page's data.json; the 133-test suite checks that no number drifts. 

git clone https://github.com/pablohuidobrogarcia/credit-risk-modeling.git
cd credit-risk-modeling

python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

# download the Lending Club data (see README) into data/raw/, then:
python -m src.pipeline all          # full modelling run
python -m src.pipeline figures      # rebuild the site figures + docs/data.json
python -m pytest                    # full test suite, incl. number-integrity checks
python -m src.report_tables --check # verify README numbers against summary.json
